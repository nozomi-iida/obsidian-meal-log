## 補足

### 並列実行について

`(P)` を付けたのは 2.1 と 2.2 の 2 つのみ。認証判定とアプリマニフェストは責務の境界が重ならず、
触れるファイルも異なるため同時に進められる。

以下は並列にできない。

- **1.1 と 1.3** — どちらもコマンド定義のためにパッケージ定義ファイルを変更する。同じファイルを奪い合う
- **1.2 と 2.2** — どちらも既存のレイアウトファイルを触る。1.2 の整形を先に済ませることで順序上解決している
- **3.1** — 2.1 の検証関数に依存する。それが無ければ関門は判定できない

### 仕様書の変更はタスクに含めない

4.2 の確認が失敗した場合、設計書には退避策（マニフェストとアイコンのみを適用範囲から外す）が
記されている。ただしその適用は**アクセス制御の適用範囲の変更**にあたり、設計書の
Revalidation Triggers に該当する。実装の中で自動的に行わず、報告して人の判断を仰ぐ。

## Implementation Notes

- **1.1**: Biome 2.x は Tailwind CSS v4 の `@theme` などを解釈できず、`globals.css` でパースエラーになる。`css.parser.tailwindDirectives` を有効にすると解消する
- **1.1**: 検査の対象から `public`（外部提供のアセット。ロゴ SVG が a11y ルールに抵触する）と `.kiro`（cc-sdd が管理する仕様書とテンプレート。整形すると更新時に競合する）を外した。設計書は「node_modules と .next を除く全体」としており、**記述と差異がある**
- **1.1**: 整形の字下げを既定のタブからスペース 2 に変更した。既存コードに揃えるため。この結果、`create-next-app` が生成したファイルは既に規約に適合しており、**1.2 の変更対象が無くなった**

### 本 spec に含めないもの

要件と設計の合意に従い、以下はタスク化していない。

- ホーム画面への追加と全画面起動の実機確認 — 利用者が別途行う
- 意匠を持つアイコンの作成 — 配置前に別タスクで行う
- 公開環境への配置作業
- 関門を直接呼び出す自動テスト — 実験的な API に依存するため行わず、4.1 の確認で担保する
